# SwiftUI 版设计差异审计与优化计划

## Current Baseline

- 当前 SwiftUI as-built 基线见 [`../current/`](../current/README.md)。
- 产品语义和交互契约见 [`../product-mental-model.md`](../product-mental-model.md) 与 [`../design/`](../design/README.md)。

## P0 开工裁决记录

本节记录 2026-07-07 P0 开工前 Flutter 体验语义审计后的用户裁决。P0 实现按下表推进；后续 P1a / P1b / P2 仍在阶段开工前各自做一次小裁决，不一次性把所有阶段提前锁死。

| 裁决项 | 结论 | SwiftUI 实现边界 |
| --- | --- | --- |
| 热力图位置 | 展开后成为导航栏下方的稳定主页上下文区域，参与主页布局，不作为独立漂浮卡片。 | 优先用现有首页布局、`safeAreaInset` / 顶部容器 / transition 参数解决；不复刻 Flutter `SliverPersistentHeader`。 |
| 热力图语义 | 点月 / 点日都是时间定位 `anchor`，不是筛选；只改变时间轴定位和时间上下文标记，不改写 `activeFilter`。 | 保持 `heatmapFocusDate` / `activeFilter` 双状态源。月份锚点落到该月在当前口径下的真实记录，而不是伪造月份节点。 |
| 月份选择 | 月份选择需要落地，但入口隐藏在热力图月份标记中，不额外做强按钮。点月后，用当前设置页主色一致的轻微透明蒙层覆盖对应月份的热力图区域。 | 月份标记可用 `Button` 语义实现；选中蒙层在现有热力图自定义组件内小范围绘制，颜色消费 `ThemeManager` 主色，透明度后续真机调参。 |
| 左滑删除 | 首页 Moment 左滑软删除进垃圾箱，无确认。交互参考 iOS 闹钟列表：轻扫露出删除按钮，继续滑动按钮拉长；恢复是反向生命周期动作。 | 当前时间轴使用 `List` 作为成熟 swipe action 宿主，但 `List` 不参与轨道定位。删除交互集中在行级 `.swipeActions`，轨道坐标由 `TimelineViewportView` / `TimelineGeometry` 独立管理，不牵动查询、路由和数据层。 |
| 左滑时的时间轴 | 左滑操作态中，日期、心情节点、moment 气泡作为一个记录整体左移；不能出现气泡移动但轨道断裂或节点脱离的割裂感。 | 组件设计已解耦“连续阅读态的轨道”和“单条操作态的整体位移”。轨道由 `TimelineRailSceneLayer` 场景层绘制，阅读单元操作层只负责横向位移，二者共同消费 `TimelineGeometry` 坐标合同。 |
| 节点与气泡 | 心情节点和气泡尾巴必须建立几何绑定，尖角应指向或贴近节点中心。 | 先通过行布局常量和尾巴参数调优；截图验证失败时再做小范围 Shape/Layout 调整。 |
| 上下文标记 | 顶部 context chips 正式表达 tag / mood / time 三类上下文，筛选与定位可并存、可独立清除。 | 优先保留现有 `TimelineContextMarkerBar`，只补必要的聚合清除入口和视觉关系。 |

## Pre-Implementation Gate

HeatMoment2 是对 `/Users/admin/Downloads/Code/HeatMoment` 中 Flutter 项目的 SwiftUI 升级复刻。P0、P1a、P2 开始写 SwiftUI 代码前，必须先完成一次 Flutter 体验语义评审。评审对象是原 Flutter 项目的相关文档与代码，目标是提取它的设计优点和交互心智，而不是复制 Flutter widget、状态管理、像素数值或内部实现。

评审输出必须整理成可枚举清单，至少包含：

| 字段 | 说明 |
| --- | --- |
| Flutter 参考点 | 具体文档或代码路径，以及它表达的体验语义。 |
| 是否值得继承 | 标记为“继承理念 / SwiftUI 化改写 / 不继承 / 需要用户裁决”。 |
| SwiftUI 实现边界 | 优先使用的成熟组件或少量参数调整；必须自定义时说明原因。 |
| 用户需裁决项 | 存在歧义时给出互斥选项，不在未裁决前进入代码实现。 |

若评审中出现“哪些需要实现 Flutter 的设计理念、哪些不需要”的不确定项，先把它们整理成选择题交给用户确认。用户确认前，不把这些项写成实现任务，也不开始对应代码改动。

裁决记录先落在本计划对应工作项下，作为进入实现的 gate 证据；裁决影响长期契约时，再同步到 `docs/product-mental-model.md` 或 `docs/design/`；裁决对应已实现事实时，落地后再同步到 `docs/current/`。

6. 外观页审计（P2）
   - 参考 Flutter 外观详情页的设计理念：外观轴分离为显示模式、主色、背景纹理；照片显示作为内容行为偏好单独表达，不和主题轴混为一类。

   - 预览必须消费 SwiftUI 当前真实主题语义（如 `ThemeManager` 暴露的背景、文字、强调色、心情色、纹理状态），不能做成与实际界面脱节的静态演示样式。

   - SwiftUI 实现优先使用 `List` / `Section` 保持设置页原生性；选项布局用 `LazyVGrid` 或横向 `ScrollView` 适配宽度；预览卡只封装小型视觉样本，不引入 Flutter 的完整皮肤系统、开发者隐藏轴或跨轴 registry。

## Acceptance

- 文档层：
  - `docs/current/` 只写当前 SwiftUI 已实现事实。
  - `docs/design/` 只写产品/交互契约，不混入“当前偏移”。
  - `docs/plans/implementation-plan.md` 只保留未完成差距、计划工作和验收条件。
  - P0、P1a、P2 开工前已有 Flutter 体验语义评审清单；存在歧义时已有用户裁决记录。
  - 筛选呈现已裁决为首页就地半屏 sheet；标签创建归属已裁决并同步为设置页集中管理，公理层、设计层、current 层和计划层之间不再保留互相矛盾的描述。

- 产品层：
  - 首页仍是唯一主场景。
  - 时间轴仍表达连续时间、心情节点和内容气泡的绑定。
  - 热力图仍只定位，不筛选。
  - Sheet 任务路径不超过入口 sheet + 一个详情层。
  - 日期/时间等短选择不打断当前编辑上下文。
  - 外观页能让用户直接感知亮/暗、主色、纹理和图片展示的真实差异。

- 工程层：
  - 优先使用 SwiftUI 成熟组件：`sheet`、`popover`、`NavigationStack`、`DatePicker`、`List`/`ScrollView`、`Menu`、`swipeActions`；当成熟组件的内部结构破坏时间轴骨架时，先重构骨架边界，让系统组件只承担它擅长的滚动、选择和行级操作语义；只有在用户裁决系统组件无法满足产品语义后，才允许小范围专用实现。
  - Flutter 只作为体验语义参考，不作为实现结构、像素数值或自定义组件数量的约束。
  - 只在时间轴气泡、热力图、上下文标记、主题预览等产品语义必须表达处自定义。
  - 不为复刻 Flutter 的内部实现而重写系统导航、系统 sheet 动画或基础输入控件。

- 验证层：
  - 文档链接检查通过。
  - 每个后续代码优化项至少运行对应的窄测试或 UI 测试；无法运行时在 current 或计划验收证据中说明原因。
