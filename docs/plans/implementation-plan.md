# SwiftUI 版设计差异审计与优化计划

## Current Baseline

- 当前 SwiftUI as-built 基线见 [`../current/`](../current/README.md)。
- 产品语义和交互契约见 [`../product-mental-model.md`](../product-mental-model.md) 与 [`../design/`](../design/README.md)。
- P0 / P1a 的视觉与交互基线以 Flutter 当前实现为体验参考：复用其“主页不下沉、半屏筛选、即时生效、选择后不关闭、手动下滑关闭、时间轴连续、节点与气泡绑定”的体验语义；不照搬 Flutter 内部实现、widget 结构或像素数值。
- SwiftUI 实现策略优先使用成熟系统组件和少量参数调整：`sheet` / `presentationDetents` / `popover` / `NavigationStack` / `List` / `Section` / `Button` / `LazyVGrid` / `ScrollView` / `swipeActions` / `DatePicker`。只在时间轴气泡、心情节点、热力图、主题预览这类产品语义无法由系统组件表达处做小范围自定义。

## P0 开工裁决记录

本节记录 2026-07-07 P0 开工前 Flutter 体验语义审计后的用户裁决。P0 实现按下表推进；后续 P1a / P1b / P2 仍在阶段开工前各自做一次小裁决，不一次性把所有阶段提前锁死。

| 裁决项 | 结论 | SwiftUI 实现边界 |
| --- | --- | --- |
| 热力图位置 | 展开后成为导航栏下方的稳定主页上下文区域，参与主页布局，不作为独立漂浮卡片。 | 优先用现有首页布局、`safeAreaInset` / 顶部容器 / transition 参数解决；不复刻 Flutter `SliverPersistentHeader`。 |
| 热力图语义 | 点月 / 点日都是时间定位 `anchor`，不是筛选；只改变时间轴定位和时间上下文标记，不改写 `activeFilter`。 | 保持 `heatmapFocusDate` / `activeFilter` 双状态源。月份锚点落到该月在当前口径下的真实记录，而不是伪造月份节点。 |
| 月份选择 | 月份选择需要落地，但入口隐藏在热力图月份标记中，不额外做强按钮。点月后，用当前设置页主色一致的轻微透明蒙层覆盖对应月份的热力图区域。 | 月份标记可用 `Button` 语义实现；选中蒙层在现有热力图自定义组件内小范围绘制，颜色消费 `ThemeManager` 主色，透明度后续真机调参。 |
| 左滑删除 | 首页 Moment 左滑软删除进垃圾箱，无确认。交互参考 iOS 闹钟列表：轻扫露出删除按钮，继续滑动按钮拉长；恢复是反向生命周期动作。 | 优先覆盖 SwiftUI 成熟 `.swipeActions` 行为，不为复刻 Flutter `SwipeActionCard` 自定义完整滑动系统。 |
| 左滑时的时间轴 | 左滑操作态中，日期、心情节点、moment 气泡作为一个记录整体左移；不能出现气泡移动但轨道断裂或节点脱离的割裂感。 | 组件设计要解耦“连续阅读态的轨道”和“单条操作态的整体位移”。若系统 `List` 行背景导致断裂，再小范围调整 rail 绘制归属。 |
| 节点与气泡 | 心情节点和气泡尾巴必须建立几何绑定，尖角应指向或贴近节点中心。 | 先通过行布局常量和尾巴参数调优；截图验证失败时再做小范围 Shape/Layout 调整。 |
| 上下文标记 | 顶部 context chips 正式表达 tag / mood / time 三类上下文，筛选与定位可并存、可独立清除。 | 优先保留现有 `TimelineContextMarkerBar`，只补必要的聚合清除入口和视觉关系。 |
| 文档漂移 | “筛选就近浮窗”旧表述作废；首页筛选统一为就地半屏 sheet。编辑页字段选择仍保持就近 popover。 | 同步 `docs/design/`，current 只在代码落地后回写。 |

## Remaining Gaps

| 主题 | 当前缺口 | 审计重点 |
| --- | --- | --- |
| 主页心智模型 | 时间轴、热力图、节点、气泡是产品主场景骨架，当前仍需真机视觉审计。 | 优先确认主页是否仍表达“时间流 + 心情节点 + 内容气泡”，而不是普通记录列表。 |
| 筛选 sheet 控件 | 筛选呈现已裁决为首页就地半屏 sheet；当前 sheet 内仍缺显式“全部心情”和“清除全部”。 | 保持当前 half-sheet 心智模型，同时补齐 Flutter 筛选体验里的直接重置能力。 |
| 设置 sheet chrome | 设置页当前有显式“关闭”按钮。 | 判断是否应依赖系统下滑关闭，减少临时 sheet 的页面感。 |
| Sheet 深度 | 当前主要路径保持两层，但设置子页、Pro、标签创建、筛选创建标签仍需按完整用户路径审计。 | 保持“入口 sheet + 一个详情层”为上限；超过两层要改 IA 或呈现方式。 |
| 热力图上下文位置 | 当前热力图是顶部 overlay 卡片。 | 期望方向是展开后作为导航栏下方稳定上下文区域参与主页布局，而不是临时漂浮卡片。 |
| 时间轴比例 | 代码已有连续竖线、节点和气泡尾巴，但仍需视觉审计 x 坐标、比例、滑动状态和节点对齐。 | 先定时间轴固定 x、节点中心、气泡起点和尖角目标点，再调 padding。 |
| 节点与气泡绑定 | 代码已有尾巴和节点同排，但需用真机截图确认尖角是否真正对准节点。 | 不把记录退化成“图标 + 卡片”的普通列表。 |
| 外观页视觉语义 | 当前外观页主要是列表行和勾选。 | 参考 Flutter 外观页的“轴分离 + 真实预览”理念，用小型预览表达背景、主文字、副文字、强调色、节点色和纹理效果。 |
| 背景纹理闭环 | `backgroundTexture` 有设置和持久化，首页未绘制网格/点阵。 | 设置项必须有用户可见效果。 |
| 图片展示闭环 | `imageDisplayMode` 有设置和持久化，气泡图片未切换滚动/轮播。 | 保持照片显示是内容行为偏好，不被主题改动牵连。 |
| 亮色主题细节 | 除 `.normal` 外的亮色心情色仍待确认。 | 亮色不是只换背景，还要保证文字、节点、热力图和统计的可读性。 |

## Pre-Implementation Gate

HeatMoment2 是对 `/Users/admin/Downloads/Code/HeatMoment` 中 Flutter 项目的 SwiftUI 升级复刻。P0、P1a、P2 开始写 SwiftUI 代码前，必须先完成一次 Flutter 体验语义评审。评审对象是原 Flutter 项目的相关文档与代码，目标是提取它的设计优点和交互心智，而不是复制 Flutter widget、状态管理、像素数值或内部实现。

评审输出必须整理成可枚举清单，至少包含：

| 字段 | 说明 |
| --- | --- |
| Flutter 参考点 | 具体文档或代码路径，以及它表达的体验语义。 |
| 是否值得继承 | 标记为“继承理念 / SwiftUI 化改写 / 不继承 / 需要用户裁决”。 |
| SwiftUI 实现边界 | 优先使用的成熟组件或少量参数调整；必须自定义时说明原因。 |
| 用户需裁决项 | 存在歧义时给出互斥选项，不在未裁决前进入代码实现。 |

若评审中出现“哪些需要实现 Flutter 的设计理念、哪些不需要”的不确定项，先把它们整理成选择题交给用户确认。用户确认前，不把这些项写成实现任务，也不开始对应代码改动。

裁决记录先落在本计划对应工作项下，作为进入实现的 gate 证据；裁决影响长期契约时，再同步到 `docs/product-mental-model.md` 或 `docs/design/`；裁决对应已实现事实时，落地后再同步到 `docs/current/`。

## Planned Work

1. 建立审计表
   - 按主页、编辑页、设置页、外观页、全局层级五组整理偏移。
   - 每项使用“当前表现 / 偏移点 / 期望设计 / SwiftUI 实现边界 / 验收方式”格式。
   - 对 P0、P1a、P2 项，先完成 Pre-Implementation Gate 的 Flutter 体验语义评审；评审结论进入审计表后，再拆实现任务。

2. 筛选呈现闭环（已裁决，P1a 补齐控件并验证）
   - 首页筛选归属“就地选择层”的半屏 sheet，不是导航式任务页，也不进入任务卡片栈。
   - 心情筛选为单选，可切回全部心情；标签筛选为多选，多个标签采用 AND 语义；“清除全部”同时移除心情和标签筛选。
   - 筛选点选即时作用于首页时间轴、上下文标记和热力图口径；sheet 不因选择条件自动关闭。
   - 当前 SwiftUI 已覆盖 half-sheet、即时生效、标签 AND、选择后不自动关闭和筛选内新建标签；仍需补显式“全部心情”和“清除全部”控件，并验证 drag handle / 系统下滑关闭 / 标签 AND 的可见交互。
   - 实现优先使用现有 `sheet` detent、`NavigationStack`、`List` / `Section`、`Button` / `Label` 和系统 drag 手势；不为了复刻 Flutter 的 `ChoiceChip` 或 bottom sheet 内部结构重写自定义容器。

3. 主页审计（P0）
   - 审计并实现热力图展开位置：从当前顶部 overlay 卡片，调整为导航栏下方稳定上下文区域。
   - 补齐热力图点月能力：月份标记作为隐性入口；点月后显示主色低透明蒙层覆盖该月热力图区域；点月 / 点日都只写时间定位 anchor，不改变筛选。
   - 审计时间轴固定 x 坐标、节点中心点 x/y、气泡起点 x、气泡尖角目标点。
   - 审计日期列、节点列、气泡列的比例关系。
   - 审计左滑记录时，日期、心情节点、moment 气泡是否作为一个记录整体左移；连续轨道不能断裂，节点不能脱离时间线。
   - 保留首页软删除进垃圾箱且无需确认；删除交互优先用系统 `.swipeActions` 达成类似 iOS 闹钟列表的轻扫露出、继续滑动拉长效果。
   - 审计筛选标记和时间定位标记在热力图展开、标题折叠、空态下的关系。

4. Sheet 层级审计（P1b）
   - 判断设置根 sheet 是否移除左上关闭按钮。
   - 逐条检查设置子页、Pro、标签创建、筛选创建标签是否仍在“最多两层”的任务范围内。

5. 编辑页局部选择审计（P1b）
   - 保留日期/时间 popover 作为正向范式。
   - 只检查它与脏数据关闭、保存后回上下文、VoiceOver 焦点的衔接，不重做基础 picker。

6. 外观页审计（P2）
   - 参考 Flutter 外观详情页的设计理念：外观轴分离为显示模式、主色、背景纹理；照片显示作为内容行为偏好单独表达，不和主题轴混为一类。
   - 为模式、主色、背景纹理、图片展示定义可感知预览。模式预览应体现明暗背景、面板/导航层、主文字/副文字和当前强调色；主色预览用 swatch 和选中态即可；背景纹理预览应展示网格/点阵/无纹理的真实差异；图片展示预览只表达滚动/轮播行为，不改变颜色语义。
   - 预览必须消费 SwiftUI 当前真实主题语义（如 `ThemeManager` 暴露的背景、文字、强调色、心情色、纹理状态），不能做成与实际界面脱节的静态演示样式。
   - 补齐 `backgroundTexture` 和 `imageDisplayMode` 的实际消费路径计划。
   - 保持主色、心情色、危险色三套语义分离。
   - SwiftUI 实现优先使用 `List` / `Section` 保持设置页原生性；选项布局用 `LazyVGrid` 或横向 `ScrollView` 适配宽度；预览卡只封装小型视觉样本，不引入 Flutter 的完整皮肤系统、开发者隐藏轴或跨轴 registry。

7. 验证与关闭（P3）
   - 每个优化项落地后，先更新 `docs/current/` 中的 as-built 事实。
   - 对应计划项只保留验收证据或标记为已关闭。
   - 每次关闭筛选相关项前，重新检查 `docs/product-mental-model.md`、`docs/design/`、`docs/current/` 与本计划，确认没有把首页筛选误写回“就近 popover”或“任务卡片 sheet”。
   - 最小验证优先使用现有脚本和相关 UI/单元测试。

## Acceptance

- 文档层：
  - `docs/current/` 只写当前 SwiftUI 已实现事实。
  - `docs/design/` 只写产品/交互契约，不混入“当前偏移”。
  - `docs/plans/implementation-plan.md` 只保留未完成差距、计划工作和验收条件。
  - P0、P1a、P2 开工前已有 Flutter 体验语义评审清单；存在歧义时已有用户裁决记录。
  - 筛选呈现已裁决为首页就地半屏 sheet；公理层、设计层、current 层和计划层之间没有互相矛盾的描述。

- 产品层：
  - 首页仍是唯一主场景。
  - 时间轴仍表达连续时间、心情节点和内容气泡的绑定。
  - 热力图仍只定位，不筛选。
  - Sheet 任务路径不超过入口 sheet + 一个详情层。
  - 日期/时间等短选择不打断当前编辑上下文。
  - 外观页能让用户直接感知亮/暗、主色、纹理和图片展示的真实差异。

- 工程层：
  - 优先使用 SwiftUI 成熟组件：`sheet`、`popover`、`NavigationStack`、`DatePicker`、`List`/`ScrollView`、`swipeActions`、`Menu`。
  - Flutter 只作为体验语义参考，不作为实现结构、像素数值或自定义组件数量的约束。
  - 只在时间轴气泡、热力图、上下文标记、主题预览等产品语义必须表达处自定义。
  - 不为复刻 Flutter 的内部实现而重写系统导航、系统 sheet 动画或基础输入控件。

- 验证层：
  - 文档链接检查通过。
  - 每个后续代码优化项至少运行对应的窄测试或 UI 测试；无法运行时在 current 或计划验收证据中说明原因。
  - 主页截图中，节点中心、气泡尖角和时间轴能形成明确绑定。
  - 左滑记录时，日期、心情节点、moment 气泡整体左移；时间轴竖线不出现视觉断裂。
  - 热力图展开时，视觉上仍属于主页顶部上下文，而不是漂浮在内容上的独立卡片；点月后当前月份区域有主色低透明选中蒙层。
  - 外观页截图能直接看出亮/暗、背景、主文字、副文字、强调色和节点色差异。
  - 外观页预览与实际主题消费路径一致；切换外观项后，预览和已接入的真实界面元素使用同一套主题语义。
