# 10 · 安全、隐私锁与隐私合规

> 职责：定义「心绪日记 / 时刻」的隐私锁 / 面容解锁能力（技术方案、设置开关、锁触发时机、无障碍），以及整体隐私合规立场（无自有服务器、隐私清单、隐私营养标签、静态协议页）。

## 10.1 隐私锁 / 面容解锁

### 10.1.1 技术方案

使用 `LocalAuthentication` 框架：
- 优先 `LAContext.canEvaluatePolicy(.deviceOwnerAuthenticationWithBiometrics)` 走 Face ID / Touch ID；
- 生物识别不可用（未注册、被系统锁定、设备不支持）时兜底为 `.deviceOwnerAuthentication`（系统密码）`[观测确认："无生物识别兜底"]`；
- 若设备既无生物识别也未设置任何锁屏密码，「面容解锁」开关应在设置页禁用/隐藏，避免出现「开了锁但永远验证不了」的死锁状态 `[设计决策]`。

### 10.1.2 设置页开关

- 「面容解锁」行为 Face ID 图标 + 系统开关，截图为关闭态 `[真机确认]`。开关状态本身为设备级本地偏好（建议存 UserDefaults，非敏感信息，是否需要 Keychain 存储取决于是否要防越狱篡改，评估为不必要的过度设计，`[设计决策]`），**不参与 iCloud 同步**（同一账号下不同设备可能希望不同的锁定策略，如 iPad 常驻家中可不锁），已采纳默认：不跨设备同步（设备级本地偏好）。

### 10.1.3 锁触发时机

- App 冷启动（`scenePhase` 从 `.background`/未启动 → `.active`）且开关开启 → 展示 `PrivacyLockView`，验证通过前不渲染任何 Moment 内容 `[设计决策]`。
- App 从后台恢复且开关开启 → 同样触发锁屏（个人日记类隐私敏感场景采用「立即锁定」策略而非计时宽限期，`[设计决策]`，如产品需要宽限期需另行确认）。
- 多任务切换器（App Switcher）快照与录屏防护：在 `scenePhase == .background` 时用品牌 Logo/纯色遮罩覆盖真实内容再进入后台快照，防止敏感内容出现在多任务预览中 `[真机确认要求"多任务遮罩" + 设计决策实现方式]`。

### 10.1.4 与隐私声明一致性

生物识别/密码验证完全由系统 `LocalAuthentication` 框架在设备本地完成，验证结果（成功/失败）与任何生物特征数据都不会离开设备、不上传给开发者或第三方，符合「不收集数据」的隐私立场，并与 `09-icloud-sync.md` iCloud 同步的隐私边界表述一致 `[观测确认]`。

### 10.1.5 无障碍

`PrivacyLockView` 标记 `accessibilityAddTraits(.isModal)`，防止 VoiceOver 焦点穿透到底层内容；验证方式主要依赖系统级 Face ID/密码交互，天然具备 VoiceOver 支持，不需要额外自定义手势覆盖系统行为。

## 10.2 隐私合规

- 无自有服务器，图片/文本仅存本地与用户个人 iCloud 私有库，不接入第三方追踪/分析 SDK `[观测确认 + 设计决策]`。
- 需提供隐私清单（Privacy Manifest）声明 `LocalAuthentication` 生物识别 API 使用目的、CloudKit 使用范围。
- App Store 隐私「营养标签」应可如实声明「未收集与用户身份关联的数据」，因架构上不存在自有后端可收集数据。
- 关于页「隐私协议」/「使用条款」为静态文本页（本地渲染或轻量 WebView），不涉及动态数据请求。
