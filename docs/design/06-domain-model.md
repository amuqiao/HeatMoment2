# 06 领域模型与契约

> **本文职责**：定义「时刻」App 的核心领域枚举与限额契约。本章列出的内容是**下游可依赖的稳定契约**——情绪枚举的顺序与 rawValue、免费/Pro 限额数值，是视觉配色（`05-design-system.md`）、i18n 文案 key、数据持久化字段（`07-data-persistence.md`）、订阅与商业化（`11-monetization.md`）等多处功能共同引用的权威定义，不得擅自调整。

## 1. 情绪模型契约

情绪是 `Moment` 的必选属性，也是时间轴心情节点、筛选、心情统计三处功能共同依赖的核心枚举。本节定义的顺序与 rawValue 是**下游可依赖的稳定契约**：心情配色（见 `05-design-system.md`）、i18n 文案 key、SwiftData 持久化字段均以此为准，不得擅自调整顺序或增删项 `[真机确认]`。

### 1.1 枚举定义

```swift
/// 情绪枚举：8 种并列情绪，非线性量表。
/// rawValue 一旦发布上线即视为持久化契约，禁止重排/复用旧值，
/// 只能在末尾追加新 case（若产品未来扩展情绪种类）。
enum Mood: Int, CaseIterable, Codable, Identifiable, Sendable {
    case normal    = 0  // 😀 正常   Normal
    case happy     = 1  // 😄 开心   Happy
    case sad       = 2  // 🙁 难过   Sad
    case anxious   = 3  // 🥶 焦虑   Anxious
    case fearful   = 4  // 😱 恐惧   Fearful
    case angry     = 5  // 😡 愤怒   Angry
    case disgusted = 6  // 🤮 厌恶   Disgusted
    case motivated = 7  // 😎 激励   Motivated

    var id: Int { rawValue }

    /// emoji 字面量，与情绪选择器 / 时间轴节点 / 心情统计条完全一致
    var emoji: String { ... }

    /// i18n key，如 "mood.normal.name"；对应 zh-Hans / en 两套本地化文案
    var localizedNameKey: String { ... }
}
```

### 1.2 排序与展示位置一致性

`Mood.allCases`（自然顺序 = rawValue 升序）必须在以下三处保持**完全一致的展示顺序**，任一处调换顺序都视为破坏契约 `[真机确认]`：
1. `MoodPickerView`（编辑器情绪下拉列表，8 项 + 当前选中项 ✓）
2. `MoodStatsView`（心情统计条形图从上到下顺序）
3. `FilterPanelView`（按心情筛选时的候选列表顺序）

页面级交互与 View 说明见 `04-screen-specs.md`。

### 1.3 语义分类（供统计/未来扩展使用，非当前必须 UI）

以下情绪效价（valence）分类是心理学常识层面的合理推导，**当前 25 张真机截图未展示任何按效价分组/着色的 UI**，仅作为数据契约的补充语义，供未来「情绪趋势/心理健康类洞察」等功能按需消费，不强制在 MVP 任何页面呈现 `[设计决策]`：

| 情绪 | 效价 | 说明 |
| --- | --- | --- |
| 正常 normal | 中性 | 基线状态 |
| 开心 happy | 积极 | |
| 难过 sad | 消极 | |
| 焦虑 anxious | 消极 / 唤起 | |
| 恐惧 fearful | 消极 / 唤起 | |
| 愤怒 angry | 消极 / 唤起 | |
| 厌恶 disgusted | 消极 | |
| 激励 motivated | 积极 / 唤起 | |

颜色映射（每种情绪对应的具体色值）由视觉规格定义，见 `05-design-system.md`；本章只保证颜色可以稳定地按 `Mood.rawValue` 或 `Mood` case 做 1:1 查表映射。

### 1.4 心情的符号与心情色契约

心情不仅是一个 rawValue，还是一套**贯穿全局的识别符号**。以下为下游可依赖的稳定契约（依公理层《产品心智模型》公理1）`[设计决策,依公理1]`：

- **每个情绪绑定唯一「心情色」**：8 情绪各对应一个确定的心情色，与 `Mood` case 做 1:1 查表映射（具体色值见 `05-design-system.md` §5.4，本章不重复色值，只保证映射稳定）。
- **心情色是跨位置的一致数据语义**：同一情绪的心情色在**时间轴心情节点、热力图日期格、心情统计条形**三处表达同一个情绪身份，不是任何一处的局部装饰，也不存在「统一色点／仅用于统计」的说法；心情色不随主题主色变化（主色只驱动强调色，心情色是独立数据语义色）。
- **心情的符号组成** = 名称 / emoji / 图标 / 心情色 / 节点形态。emoji 用于轻量识别与筛选状态标记提示，图标用于筛选菜单与编辑入口的明确识别；是否存在独立于 emoji 的专有图标形态待实测/设计确认（见 `05-design-system.md`），不影响本契约。

下游（配色、热力图着色口径、i18n、持久化）均以本契约为准，不得把心情色降级为局部装饰，或以单色替代按情绪着色。

## 2. 免费 / Pro 限额（唯一权威）

以下限额是全 App 的唯一权威定义。记录流程（见 `03-user-flows.md`）、数据模型的计数口径（见 `07-data-persistence.md`）、订阅与 Paywall 触发（见 `11-monetization.md`）均引用本表，不得在其他位置重复或另行定义限额数值。

| 能力 | 免费用户 | Pro 用户 | 依据 |
|---|---|---|---|
| Moment（日记）篇数 | 最多 10 篇 | 无限 | `[真机确认]` |
| 单篇照片数 | 每篇最多 3 张 | 无限 | `[真机确认]` |
| 标签数 | 最多 3 个 | 无限 | `[真机确认]` |
| iCloud 同步 | 具备（宣传语「同步个人 icloud」） | 具备 | `[真机确认]` |
| 价格 | — | ¥6.0 / 月（自动续期） | `[真机确认]` |
| 终身买断 | — | 一次性买断（价格待定） | `[设计决策，超出原 App]` |

> 限额计数口径要点（详见 `07-data-persistence.md`）：
> - Moment 10 篇上限统计**所有尚未物理删除的记录（含垃圾箱内 `isDeleted==true` 的）**——软删除不释放配额，须在垃圾箱内彻底删除才腾出名额；
> - 单篇照片 3 张以该 Moment 的 `images.count` 校验；
> - 标签 3 个以 `Tag` 表总行数为准（标签无软删除概念，删除即物理删除）。
