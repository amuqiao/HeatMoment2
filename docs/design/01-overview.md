# 产品概述与范围

> 职责说明：界定「心绪日记 / 时刻 / Moodments」这款 App 的产品定位、目标读者与平台交付范围，为其余设计文件提供共同背景。

> **上游依据**：本设计文档体系是产品**公理层**《[产品心智模型](../product-mental-model.md)》的**下游实现**。公理层回答「产品是什么、由哪些对象构成、语义与规则」，本目录回答「真机是什么样、如何用 SwiftUI 还原」。任一设计决策都应能回指公理层的对象或公理；若与公理冲突，是设计错了。

## 目的与读者

面向要复刻本 App 的产品/设计/工程团队，提供一份可直接进入排期的实现设计。它回答的是「真机现在是什么样、如何用 SwiftUI 还原」，而非「产品应该长什么样」。

## 平台范围

iPhone + iPad（iOS/iPadOS 17.0+），SwiftUI。设计稿均为 iPhone；iPad 走自适应布局，不新建独立设计稿 `[设计决策，已确认]`。

## 迭代排期分层：先核心，后支撑 `[设计决策]`

心智模型把对象分为**核心心智对象**与**支撑能力**两层；排期须尊重这一层级——支撑能力不得在核心体验成型前抢占工期。

| 层级 | 内容 | 说明 |
| --- | --- | --- |
| **P0 · 核心体验** | 记录（时刻/心情/标签/图文/发生时间）、时间轴（气泡·心情节点·上下文标记）、回看（热力图·心情统计）、编辑（就近浮窗·任务卡片） | 产品的心智主线，先打磨到位 |
| **P1 · 支撑能力** | iCloud 同步、Face ID/密码隐私锁、语言切换、订阅（含终身买断） | 服务于记录的安全与边界；不是核心心智对象，**排在核心成型之后**接入 |

理由：`iCloud / Face ID / 语言 / 终身买断`在心智模型中被明确定位为**支撑能力而非核心对象**（见《[产品心智模型](../product-mental-model.md)》第一层）。它们对产品价值是「保障」而非「主线」，过早投入会稀释核心体验的打磨。此分层仅约束**投入顺序与优先级**，不代表支撑能力不做。
