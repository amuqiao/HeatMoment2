# 设计系统与视觉规格

> 本文定义「时刻」App 的视觉设计系统与主题规格：设计语言基调、全局配色系统、主题参数矩阵（模式/主色/背景纹理/图片展示及其影响边界与异常反馈）、情绪→颜色映射、气泡时间轴、组件规格、关键页面视觉方案、字体排版、动效规范与视觉无障碍（含 WCAG 对比度核算），是所有界面还原的视觉唯一事实源。

> 本文色值凡标 `[真机确认,取色]` 均为对「设计稿/」原始截图使用像素取色直接测得（见文末取色清单）；凡标 `[设计决策]` 为截图不可直接测得、按同类范式或数学换算得出；凡标 `[观测确认]` 为真机观测或用户确认口径。数据模型、交互逻辑、订阅规则、StoreKit 相关内容不在本文范围，请参见 `06-domain-model.md`、`07-data-persistence.md` 等对应文档。

## 5.1 设计语言基调

「时刻」的视觉基调是**「精美图文时间轴日记」** `[观测确认]` 在界面上的直接翻译，具体表现为三个关键词：

1. **深色为主、克制发光**：默认外观是深色模式 + 紫色主色 `[真机确认]`。全局背景不是纯黑，而是带一点点蓝紫色调的深靛蓝（`#121221`），让主色（紫/红/蓝等高饱和强调色）和各情绪心情色的心情节点在暗背景上显得像「夜空中的光点」，呼应「记录人生中重要时刻」的产品调性。
2. **气泡感、聊天化叙事**：时间轴不是传统列表/卡片网格，而是左侧竖线 + 心情节点 + 右侧圆角气泡的**聊天记录式**布局（见本文《气泡时间轴视觉规格（TimelineHomeView）》），让「记日记」产生「与自己对话」的亲密感。
3. **组合式主题、强个性化**：主题不是三套预设皮肤，而是模式（暗/亮）× 主色（6选1）× 背景纹理（3选1）× 图片展示方式（2选1）的自由组合（见本文《主题参数矩阵》），体现「这是你自己的时刻」的产品主张。

视觉分层上采用**「品牌画布 + 系统化界面控件」**双轨策略 `[设计决策,基于取色结果]`：
- 时间轴主画布（背景纹理、气泡卡片、心情节点、悬浮按钮）使用**自定义品牌配色**，不跟随 iOS 标准分组表格色板；
- 设置、编辑器 sheet、下拉菜单等**功能性容器**大量复用 iOS 标准深色分组表格色值（`#1C1C1E` / `#2C2C2E` 分别与 Apple `secondarySystemBackground` / `tertiarySystemBackground` 深色值吻合），降低开发与系统一致性成本。

## 5.3 主题参数矩阵

主题系统由 **4 个独立参数**组合而成，来自 AppearanceThemeView（截图 173/174）`[真机确认]`：

```
外观 = 模式(暗色 | 亮色) × 主色(紫色|红色|橙色|绿色|青色|紫罗兰) × 背景纹理(网格线|点阵|无) × 图片展示(滚动|轮播)
```

### 5.3.1 模式（2 选 1）

| 模式 | 作用范围 |
|---|---|
| 暗色模式（默认） | 全局背景切换为 5.2.1 深色值，状态栏/导航栏跟随变暗 |
| 亮色模式 | 全局背景切换为 5.2.1 浅色值 |

> 注：Pro 订阅页（ProPaywallView）与关于页（AboutView）**始终强制使用亮色外观 + 固定红色强调**，不随用户此处的模式选择变化，详见本文《Pro / 关于页的「固定红」vs 主界面「可变主色」》。

### 5.3.2 主色（6 选 1，默认紫罗兰）

主色圆点在 AppearanceThemeView 的「颜色」分组中并列展示 `[真机确认]`。实测发现：6 个色块中，**蓝/红/青 3 色在暗色页与亮色页截图中测得像素值完全一致**，而**紫（默认选中态）、橙、绿在两页测得值有系统性差异** —— 这与 Apple `Assets.xcassets` 的 「Any Appearance / Dark Appearance」双值色板机制高度吻合 `[设计决策]`：选中态圆点及全局强调色（FAB、按钮、链接文字）读取的是「当前 ColorScheme 下已解析的值」，未选中的色板圆点则是静态预览色，因此只有作为「当前选中色」被实际渲染过的紫（173/174 默认选中）与红（177 亮色时间轴实测）呈现出明显的双态差异。

> 6 主色官方命名 `[观测确认]`：**紫色 / 红色 / 橙色 / 绿色 / 青色 / 紫罗兰**，默认选中「紫罗兰」。上表首行「紫色」= 靛蓝 `#5E5BE6`，末行「紫罗兰」= 薰衣草紫 `#B678F5`，二者是不同色板项，勿混淆。

| 选项 | 效果 | 依据 |
|---|---|---|
| 网格线（默认） | 时间轴背景铺满细线网格（线色见本文《配色系统：全局语义色》） | `[真机确认]` |

### 5.3.4 图片展示方式「图片」（2 选 1）

| 选项 | 效果 | 依据 |
|---|---|---|
| 滚动（默认） | 气泡内多图并排横向排布（如首屏引导卡的双色块图） | `[真机确认]` |
| 轮播 | 气泡内单图占满宽度，底部居中显示页码圆点指示器 | `[真机确认]` |

仅影响气泡卡片内图片区域的呈现，不影响图片数量限制等业务规则（见 `06-domain-model.md`）。

### 5.3.5 Pro / 关于页的「固定红」vs 主界面「可变主色」

结合截图交叉验证得出以下判断 `[设计决策,基于截图交叉比对]`：

- 截图 169（设置页，暗色 + 紫主色）与截图 175/176（关于页、Pro 页）出自**同一次真机会话**，若 Pro/关于页跟随主题应显示紫色 + 深色，但实测二者均为**浅色背景 + 固定红色强调**（返回按钮「‹设置」为红、CTA 按钮 `#FC5446`、「核销码」/「恢复购买」文字红），与用户当前选中的紫色主题**完全不符**。
- 结论：**红色是与主色解耦的独立「危险/商业动作」语义色**（数值近似主色板「红色」`#FC5447`）——真机交叉比对确认：删除、失败、购买页部分高风险或强调商业动作使用独立危险色，不跟随主色 `[观测确认]`。它统一用于：首页/垃圾箱删除动作、错误/失败提示、Pro 页 CTA 与「核销码/恢复购买」文字；同时 Pro/关于页**强制使用亮色外观**，不随用户暗/亮模式选择。
- 因此验收时不应期待删除按钮、错误提示、Pro 页危险按钮跟随用户所选主色——它们始终是危险色。设计动机：商业化/合规页面追求跨用户一致的转化与信任观感，不被个性化主题稀释。

### 5.3.6 主色影响面 / 不影响面（强调色语义边界，权威查表）

主色**不是全局换肤**，只驱动一套「强调色语义」`[观测确认]`。新增任何 UI 时按此表判断是否接入主色：凡表达「当前选中 / 可以行动 / 正在聚焦」的元素接入主色；凡表达「内容本身 / 心情语义 / 危险动作 / 阅读层级 / 结构背景」的元素不接入主色。

**跟随主色（改主色后随之变化）**：
- 主要行动入口：新建、保存、确认、返回、关闭等强调操作；
- 选中/聚焦态：筛选选中、外观选项选中、年份选择、日期/时间选择器聚焦态；
- 设置流视觉重点：设置页图标底色、入口图标、选项边框、诊断提示边框；
- 编辑体验：日期/时间 pill、标签选择、照片添加动作、可保存态；
- 预览与标签：预览页编辑入口、标签胶囊、部分标签文字/背景；
- 回看体验：热力图「今日边框」、年份选择、月份聚焦态；
- 背景纹理：开启时网格线/点阵使用主色派生的低透明度色（见本文《配色系统：全局语义色》《背景纹理「网格」（3 选 1）》）。

**不跟随主色（保持独立语义）**：
- 记录内容（标题/正文/时间/照片/标签归属/统计结果）；
- 心情色（8 情绪色是独立数据语义，见本文《情绪 → 颜色映射表》）；
- 危险色（删除/失败/Pro 页高风险动作，见本文《Pro / 关于页的「固定红」vs 主界面「可变主色」》）；
- 中性基底（背景/面板/文字/边框，由「模式」决定）；
- 照片显示行为（滚动/轮播，由「照片显示」决定，见本文《图片展示方式「图片」（2 选 1）》）；
- 开发者变体轴与未开放外观轴（气泡样式、心情节点样式、时间轴轨道样式、业务图标包、背景插画、表面材质——均非当前用户可改能力）。

> **注意矛盾点**：真机观测确认（热力图）日期选中边框当前使用**主文本色**，不属于主色影响面；而本文依据 `04-screen-specs.md` 中 `DatePickerSheetView` 依截图 165 记录的编辑器日历选中日为**主色实心圆**——因截图当时主色恰为紫、与主文本色难以区分，两者是否同一处控件、到底跟不跟随主色，需实测确认，已列入开放问题清单。

### 5.3.7 外观偏好的保存与异常反馈（AppearanceThemeView 交互）

外观修改采用「**先更新当前界面，再保存偏好**」的乐观更新策略 `[观测确认]`，视觉状态与持久化状态是两件事：
- 点选主色/模式/纹理后当前界面**立即**使用新值；
- 主色等外观保存失败：界面**不回滚**，外观页显示「外观设置保存失败，请稍后重试」；
- 照片显示保存失败：单独反馈「照片显示设置保存失败，请稍后重试」（与外观保存失败分开）；
- 本地偏好存在坏配置：使用可用默认值或迁移值继续运行，并提示「已修正 N 项本地偏好配置」。

工程上对应 `07-data-persistence.md` 的 `AppearancePreference` 的写入需返回成功/失败结果，UI 层据此在不回滚视觉的前提下展示上述提示。

## 5.4 情绪 → 颜色映射表

> **定位** `[设计决策,依公理1]`：每种情绪拥有唯一「心情色」，它是**跨时间轴心情节点、热力图日期格、心情统计条形的一致数据语义色**（依公理1），不是任何一处的局部装饰，也不存在「统一色点／仅用于统计」的说法。心情色独立于主题主色、不随主色变化（见 §5.3.6）。下表 8 情绪色值为取色/推导结果，供上述所有位置统一查表使用。

8 种情绪并列（非等级），取自编辑器情绪下拉与心情统计页顺序一致 `[真机确认]`。心情统计页（MoodStatsView，截图 170）除「正常」外其余情绪当前记录数均为 0，进度条以低透明度（「空状态」）展示；通过与卡片背景 `#2C2C2E` 反向解混合（假设空状态透明度 ≈15%，该假设由 7 条空条带回代验证，色相/色调结果与常识情绪配色高度吻合，如愤怒→红、焦虑→紫粉、恐惧→蓝紫）`[设计决策]`，估算出各情绪满值强度色，供开发按百分比渲染进度条时使用。

**心情双符号（emoji vs 图标）用途** `[真机确认 + 待实测/设计]`：心情的识别符号有两种形态——**emoji** 用于轻量识别与「当前筛选条件」状态标记的提示（时间轴筛选标记、选中态 emoji + 名称）；**图标** 用于筛选菜单与编辑入口的明确识别（如编辑器情绪选择器入口）。真机识别以 emoji 为主 `[真机确认]`；是否存在独立于 emoji 的专有图标形态、其具体造型，真机未明确 `[待实测/设计]`，实现前须实测或设计确认，不臆造具体图标。

## 5.5 气泡时间轴视觉规格（TimelineHomeView）

结构自左至右分三列 `[真机确认]`：

1. **日期列**（宽度约 64pt）：上方大号粗体「日」数字（如「17」，约 28pt Bold）+ 右侧小号「月」文字（如「5月」，约 13pt Regular 灰色）；下方独立一行显示「时:分」（如「17:06」，约 13pt Regular 次级灰）。
2. **时间线列**（宽度约 24pt）：居中贯穿整屏的 1pt 竖线（色值见本文《配色系统：全局语义色》）；竖线上叠加**心情节点圆点**，直径约 12–14pt，纯色填充为**该条时刻情绪对应的心情色**（见 §5.4）；心情色是独立数据语义色，独立于主题主色、不随主色变化（截图节点多为「正常」情绪的 `#15BEB4`，是该情绪的心情色，非固定色）`[真机确认 + 设计决策,依公理1]`。
3. **气泡卡片列**（占剩余宽度）：
   - 圆角矩形卡片，圆角半径约 20pt，背景色见本文《配色系统：全局语义色》；
   - 内边距约 16pt；
   - 标题：粗体，约 17pt，单行；
   - 正文摘要：Regular，约 15pt，次级文字色，最多约 3 行，超出以「…」截断；
   - 图片区（若有）：正文下方，横向圆角矩形缩略图（圆角约 12pt），按本文《图片展示方式「图片」（2 选 1）》的「滚动/轮播」两种模式排布；
   - 卡片左侧以一个小三角「尾巴」或缺口指向时间线节点，强化「聊天气泡」观感（截图中卡片左边缘与时间线节点水平对齐且有指示箭头造型）`[真机确认]`；
   - 卡片间垂直间距约 20–24pt。
4. 首页左滑卡片时日期、心情节点、moment 气泡作为一个记录整体左移，露出删除动作（软删除进垃圾箱），不弹二次确认 `[观测确认 + 设计决策]`；左滑删除按钮 = §5.3.5 定义的固定危险红（≈`#FC5447`），与主色解耦。交互优先使用系统 swipe action，轻扫露出删除、继续滑动按钮拉长。

## 5.9 动效规范 `[设计决策,可调]`

以下均为设计意图层面的动效建议，非最终实现约束，可在开发阶段调优：

- **气泡进场**：新气泡插入时间轴顶部时，建议轻微上滑（位移 12–16pt）+ 淡入（0→100% 透明度），时长 250–300ms，`easeOut` 曲线，配合心情节点的轻微缩放弹入（scale 0.8→1.0，`spring` 阻尼 0.7）。
- **情绪选择反馈**：MoodPickerView 中点击某一行，先给 100ms 的行高亮闪烁反馈，再执行 150ms 收起动画（整个浮层向上收缩淡出），同时触发器行的 emoji/名称做一次 200ms 的交叉淡入切换。
- **热力图/统计生长**：YearHeatmapView 与 MoodStatsView 首次出现时，建议进度条/热力格从 0 到目标值做 400–600ms 的「生长」动画（宽度/透明度插值），按格子/行的索引做 20–30ms 的错峰（stagger），制造数据「逐条浮现」的仪式感。
- **主题切换过渡**：AppearanceThemeView 内切换模式/主色/网格/图片选项时，预览卡内容应做 200ms 交叉淡入淡出，而非硬切；全局应用主题变更后返回 TimelineHomeView 时，背景色与主色的变化建议整体做 300ms 颜色插值过渡，避免生硬闪烁。
- **减弱动效偏好**：所有以上动效均应在系统「减弱动态效果」（Reduce Motion）开启时降级为纯淡入淡出或直接无动画切换，不使用位移/缩放类效果。

### 5.10.2 Dynamic Type 超大字号应对 `[设计决策]`

- TimelineHomeView 顶部栏「时刻」标题与三入口图标需保证在 `.accessibility5` 级别字号下不与右侧六边形图标重叠，建议标题允许自动缩小（`minimumScaleFactor`）或在超大字号下换行/图标下沉。
- 气泡卡片标题/摘要文字放大后，卡片高度应自适应增长（见本文《字体排版》），但摘要仍保持「3 行截断」逻辑，避免单条气泡在超大字号下占满整屏。
- 设置分组列表行（左图标 + 标题 + 右状态文字）在超大字号下，右侧状态文字（如「已同步」「简体中文」）与标题可能因空间不足产生冲突，建议超过阈值后右侧状态文字换行到标题下方或改用次行小字展示。
- 编辑器顶部日期/时间双 chip + 保存/取消文字，在超大字号下建议整体换行为两行（第一行 取消/保存，第二行 chip），避免横向挤压变形。
- MoodPickerView/标签下拉行高应随字号动态增加（非固定 52pt），避免 emoji/文字与右侧 `✓` 重叠。

### 5.10.3 色彩可辨识性

- 情绪辨识遵循「颜色 + 文字/emoji 多通道冗余」原则，不存在任何「仅凭颜色才能获取的信息」：时间轴心情节点按各情绪的心情色着色（见 §5.4、§5.5），但情绪的最终辨识不单靠节点颜色——情绪选择器（MoodPickerView）与心情统计（MoodStatsView）均带 emoji + 中文名称，单条时刻详情/编辑处显示情绪名文字，构成独立于节点颜色的冗余通道，符合色盲友好三通道（颜色/形/文字）原则；主色选择同理保留色名文字。
- 6 个可选主色应避免让色弱用户误选：红/绿是最常见色盲混淆对，当前红 `#FC5447` 与绿 `#2DAD74` 明度差异较大（红更亮更暖、绿更暗更冷），在 Deuteranopia/Protanopia 模拟下仍可通过明度区分，加上选择界面本身有「色名文字标签」（紫色/红色/橙色/绿色/青色/紫罗兰虽未在截图直接看到文字标签，建议在实现时于圆点下方或 VoiceOver 中补充文字色名，由 `12-quality-assurance.md` 落地）。
- 建议所有面向色觉障碍用户的关键判断点（情绪选择、主色选择）均保留 emoji/文字标签，不依赖用户单独看色相做决策，当前设计已天然满足此原则。
