# Product Design Logic

> 本文总结 HeatMoment 当前 App 的产品设计与交互逻辑，只描述用户体验、信息结构和行为规则，不描述实现或工程细节。

## 文档边界

本文帮助读者理解 HeatMoment 作为一款个人生活时刻记录 App 的设计方式：

- 用户记录什么。
- 用户从哪里进入核心任务。
- 信息如何被组织、回看和管理。
- 不同交互为什么采用 sheet、筛选、热力图、滑动动作和设置流。

本文不解释任何实现、工程或平台构建问题。产品事实以当前 App 实际行为为准；未实现的设想不写入本文。

## 整体模型

HeatMoment 当前围绕“把生活时刻留下来，并在之后轻量回看”组织体验。它不是社交发布工具，也不是复杂分析工具；核心设计重心是让个人记录保持低负担、可浏览、可定位、可整理。

```text
记录 Moment
  -> 在 Timeline 中浏览
  -> 通过标签、心情和热力图回看
  -> 在设置流中长期管理
```

四个产品对象共同构成当前体验：

| 对象 | 产品含义 | 用户感知 |
| --- | --- | --- |
| `Moment` | 一条生活时刻 | 发生时间、心情、标签、标题、正文和照片共同构成一段记忆 |
| `Timeline` | 默认浏览空间 | 用户回到 App 后首先看到记录按时间展开 |
| `Review` | 回看能力 | 热力图和统计把零散记录压缩成年度、月份、日期和心情分布 |
| `Manage` | 长期维护能力 | 标签、垃圾箱、外观、Pro 和关于信息集中在设置流 |

## 信息架构

HeatMoment 当前只有一个根体验：`Home Timeline`。新增、预览、筛选、热力图和设置都围绕首页展开，不把用户带进多个并列一级 Tab。

```text
Home Timeline
├── 新建 / 编辑 Moment
├── 单条 Moment 预览
├── 标签与心情筛选
├── 年度心情热力图
└── 设置流
    ├── Pro
    ├── 心情统计
    ├── 标签管理
    ├── 垃圾箱
    ├── 外观主题
    └── 关于 HeatMoment
```

这种结构让首页同时承担三个职责：

- **记录入口**：用户可以从首页直接新建 Moment。
- **浏览空间**：用户用时间轴阅读已记录内容。
- **上下文中心**：预览、编辑、筛选、回看和管理都从当前上下文展开，再回到首页。

首页顶部也对应这三个方向：左侧入口展开年度心情日历，中间标题入口打开筛选，右侧入口进入设置流。没有记录时，首页用空状态引导用户记录第一个时刻；已有记录时，底部主按钮承担快速新建入口。

## 记录设计

`Moment` 的设计不是把日记表单做复杂，而是把“时刻”压缩成几类稳定线索：

- **时间**：每条记录都有发生日期和时间，用来放回时间轴和热力图。
- **心情**：心情是记录的情绪锚点，也驱动时间轴节点、筛选和统计。
- **标签**：标签表达主题归类，帮助用户从内容维度回看。
- **标题与正文**：标题用于快速识别，正文用于保留叙事。
- **照片**：照片补充文字无法表达的场景记忆。

编辑器承担新建和编辑两种任务。日期、时间、心情、标签、文字和照片都在同一个表单中完成；日期和时间作为就地选择出现，避免用户离开当前编辑上下文。标题、正文和照片至少有一项时，记录才具备保存意义。关闭未保存表单时需要确认，防止误丢输入。

保存后，如果新记录或编辑后的记录不属于当前筛选结果，App 会给出反馈，让用户知道内容已经保存，只是不会出现在当前列表中。

## 时间轴设计

时间轴是 HeatMoment 的主阅读界面。它把 Moment 按时间组织为连续叙事，而不是把记录做成普通列表。

时间轴里的每条记录由时间戳、心情节点和气泡内容共同表达：

- 时间戳回答“这件事发生在什么时候”。
- 心情节点回答“当时的情绪是什么”。
- 气泡内容承载标题、正文摘要、标签和照片缩略图。

点击时间轴卡片进入单条预览。预览页强化单条 Moment 的阅读体验：顶部保留心情、日期和编辑入口，正文区域展示标题、标签、照片和内容。照片可继续进入查看器。

首页删除使用轻量的滑动动作：左滑露出删除动作，点击后 Moment 进入垃圾箱。这个设计把日常清理做得快捷，同时通过垃圾箱保留恢复路径。

## 回看设计

HeatMoment 的回看能力分为两层：

- **首页热力图**：用于快速观察某一年记录分布，并定位时间轴。
- **心情统计页**：用于在设置流中查看年度心情日期分布和心情统计。

首页热力图不是独立一级页面。用户从首页展开年度心情日历，选择年份、月份或日期；选择日期或月份时，App 高亮对应时间锚点并定位时间轴，而不是把首页变成一个永久的时间范围筛选器。再次选择同一锚点可以取消定位。

统计页更像长期回顾入口。它按年份呈现心情日期分布和心情数量汇总，帮助用户从“单条记录”切换到“这一年整体状态”的视角。

## 筛选设计

首页筛选用于缩小当前时间轴内容。当前可筛选维度是标签和心情。

筛选作为就地选择出现：用户打开筛选面板，选择标签或心情后仍停留在首页语境里。筛选生效后，首页显示当前条件标记，用户可以单独移除某个筛选条件，也可以清除全部。

筛选和热力图定位承担不同任务：

| 能力 | 设计目的 | 对时间轴的影响 |
| --- | --- | --- |
| 标签 / 心情筛选 | 缩小可见记录集合 | 改变当前列表内容 |
| 热力图日期 / 月份选择 | 在完整记录中定位时间段 | 高亮并滚动到相关位置 |

这个区分避免用户把“定位回看”和“条件筛选”混成同一种操作。

## 管理设计

设置流收纳不属于日常记录阅读的长期管理任务。它从首页顶部进入，并在同一张设置 sheet 内推进子页；用户返回时回到设置列表，关闭设置时回到首页。

设置流当前包含以下产品任务：

| 入口 | 产品职责 |
| --- | --- |
| Pro | 展示订阅权益、价格、购买、恢复购买和核销码入口 |
| 心情统计 | 查看年度记录分布和心情统计 |
| 标签管理 | 创建、重命名和删除标签 |
| 垃圾箱 | 恢复已删除 Moment，或彻底删除 Moment |
| 外观主题 | 调整显示模式、主色、背景纹理和照片显示方式 |
| 关于 HeatMoment | 展示应用介绍和版本信息 |

设置列表中也保留了未开放能力的占位，例如通用设置和作者其他应用。它们当前只是信息占位，不应理解为已经可用的功能。

## 标签设计

标签是轻量主题归类，不承担复杂知识库或多层分类职责。

用户可以在编辑 Moment 时创建标签，也可以在标签管理页集中创建、重命名和删除标签。当前默认标签包括“工作”“生活”“健康”，用于帮助新用户快速开始归类。创建标签受到 Pro 权益限制；达到免费数量上限时，App 会引导到 Pro 页面。

删除标签不会删除 Moment。已有记录会失去该标签关联，但内容本身保留。这让标签更接近“整理线索”，而不是内容所有权。

## 删除与恢复设计

Moment 删除采用“先进入垃圾箱，再决定是否彻底删除”的生命周期：

```text
首页 Moment
  -> 左滑删除
  -> 进入垃圾箱
  -> 右滑恢复 / 左滑彻底删除
```

首页删除不弹二次确认，因为垃圾箱提供恢复路径。垃圾箱里的彻底删除则表示用户放弃恢复机会。

标签删除不进入垃圾箱。它只移除分类线索，不移除任何 Moment，因此不使用 Moment 的软删除生命周期。

## 外观与内容偏好设计

外观页让用户调整当前体验的视觉感受，而不是改变记录内容。

当前用户可见的外观和内容偏好包括：

- 显示模式。
- 主色。
- 背景纹理。
- 照片显示方式。

照片显示方式影响时间轴照片在记录卡片中的呈现节奏，例如横向滚动或轮播。

外观调整只影响界面呈现，不影响已记录的 Moment、标签和统计数据。这个边界让用户可以放心尝试不同视觉风格，而不担心内容被重写。

## Pro 设计

Pro 当前围绕容量限制解锁展开：

- 普通用户最多记录 10 篇日记。
- 普通用户每篇日记最多保存 3 张照片。
- 普通用户最多创建 3 个标签。
- Pro 用户解锁无限日记、照片和标签。

Pro 页面可以从设置入口进入，也会在用户触达免费限制时作为上下文提示出现。购买、恢复购买、价格展示都集中在 Pro 页面中；App Store 核销码入口只在 iOS 且系统能力可用时出现。

Pro 不改变当前本地优先的产品定位，也不改变记录、回看和管理的主流程。

## 交互语言

HeatMoment 当前使用几类稳定交互语言：

| 交互 | 使用场景 | 设计目的 |
| --- | --- | --- |
| 表单任务 | 新建、编辑、标签命名 | 保持任务聚焦，并允许关闭回到原上下文 |
| 上下文详情 | 单条 Moment 预览、Pro 页面 | 在当前上下文上展开独立阅读或决策任务 |
| 管理流 | 设置及其子页 | 收纳长期管理任务，同时保留回首页路径 |
| 就地选择 | 日期、时间、筛选 | 在当前任务里完成局部选择 |
| 滑动动作 | 删除、恢复、彻底删除 | 让列表维护动作保持轻量且可预期 |
| 条件标记 | 当前筛选上下文 | 让用户看见并移除当前条件 |

这些交互共同服务一个目标：用户尽量不被带离当前语境。记录、预览、筛选、回看和管理都像从首页展开的临时任务，完成后自然回到时间轴。

## 当前不表达的产品能力

以下内容不属于当前产品设计事实：

- 云同步、社交发布、多端协同和复杂 AI 分析。
- 独立一级 Review 入口或独立 Review 页面。
- 已开放的深度时间范围筛选 UI。
- 已上线的动态皮肤市场、自定义皮肤下载或公开图标包选择。
- Face ID、语言设置和作者其他应用入口的可用功能。

如果这些能力未来实现，应先更新当前事实文档，再调整本文。
