# 产品对象交互逻辑

> HeatMoment 的交互不是一组零散页面，而是一套由产品对象串起来的体验语言：时刻承载记忆，心情定义情绪身份，标签组织主题，热力图负责回看定位，任务卡片承接临时任务。

## 文档边界

本文说明当前 HeatMoment 的产品对象、视觉符号和交互效果如何互相联动。它面向产品设计、交互梳理、视觉验收和后续需求讨论。

本文只从用户看到什么、理解什么、操作后发生什么出发，不展开实现方式。

它不是单个页面说明，也不只覆盖某几个被点名的交互；它更像一份产品对象词典：回答每个对象由哪些符号组成、有哪些状态、状态变化后会影响哪些位置。

## 整体对象模型

HeatMoment 当前围绕个人生活时刻展开。核心体验可以理解为：

```text
时刻
  是一条生活记忆
  由时间、心情、标签、文字、照片组成

时间轴
  是所有时刻的主舞台
  负责浏览、预览、删除、新建入口

心情
  是时刻的情绪身份
  贯穿节点、颜色、图标、筛选、热力图和统计

标签
  是时刻的主题线索
  负责整理、筛选和管理

上下文标记
  是当前时间轴条件的可见表达
  让用户知道现在看的是完整记录，还是某个筛选或时间位置

热力图
  是回看和定位工具
  把分散时刻压缩成年度、月份、日期和心情颜色

任务卡片
  是临时任务层
  承接预览、编辑、设置、订阅和管理任务

就近浮窗面板
  是局部选择工具
  从触发元素旁就近弹出，承接筛选、日期和时间这类短动作

删除生命周期
  是时刻从正常、垃圾箱到彻底移除的状态变化
  负责让删除可恢复、彻底删除有边界
```

这些对象共同服务一个主线：

```text
记录一个时刻
  -> 在时间轴中阅读
  -> 用心情和标签理解它
  -> 用热力图回到某段时间
  -> 用任务卡片完成编辑、预览和管理
  -> 用删除与恢复管理时刻生命周期
```

## 首页上下文对象

首页上下文对象说明“用户现在站在哪里”。它不是页面布局说明，而是一组稳定的场景符号。

它由三个符号组成：

```text
年度回看符号
  -> 表达“可以从时间回看进入”

时刻标题
  -> 表达“当前仍在主时间轴”
  -> 在有筛选时承担条件入口

管理符号
  -> 表达“进入长期管理任务”
```

“时刻”标题的状态变化只表达上下文，不表达新页面：

| 状态 | 用户感知 |
| --- | --- |
| 普通浏览 | 大标题“时刻”强调这里是主时间轴 |
| 滚动或有上下文时 | 标题收进顶部栏，仍保持“时刻”身份 |
| 已筛选时 | 标题旁的指示变为强调状态，提示当前时间轴不是完整列表 |
| 热力图展开时 | 顶部保持紧凑，给回看面板和时间轴让出空间 |

因此，“时刻”标题同时是主场景标识和筛选入口。它让用户知道自己没有离开时间轴，只是在时间轴上改变当前查看条件。

## 时刻对象

一个时刻不是普通文本卡片，而是一条生活记忆。它由几类线索共同构成：

```text
时刻
  ├── 发生时间：这件事发生在什么时候
  ├── 心情：当时是什么情绪状态
  ├── 标签：这件事属于什么主题
  ├── 标题：这条记忆如何被快速识别
  ├── 正文：具体发生了什么
  └── 照片：当时的场景证据
```

时间轴上的时刻被拆成三个阅读部件：

```text
时间戳
  -> 回答“什么时候”

心情节点
  -> 回答“当时是什么状态”

气泡内容
  -> 展示标题、正文摘要、标签和照片
```

点击时刻后进入预览。预览不是新页面跳走，而是在当前时间轴上弹出一张阅读卡片：顶部保留心情、日期和编辑入口，正文区域完整展示标题、标签、照片和内容。

## 心情对象

心情是 HeatMoment 最重要的产品对象之一。它不是单独的 emoji，也不是时间轴上的一个装饰点，而是一套情绪身份。

当前心情对象包含：

```text
心情
  ├── 名称：平静、开心、低落、焦虑、害怕、生气、厌烦、有动力
  ├── emoji：用于轻量识别和筛选状态提示
  ├── 图标：用于筛选和编辑入口中的明确识别
  ├── 心情色：用于时间轴节点、热力图和统计
  └── 节点形态：用于把情绪挂到时间轴上
```

心情对象在不同位置的表达应保持同一身份：

| 位置 | 心情如何出现 | 设计目的 |
| --- | --- | --- |
| 编辑器 | 用户选择一个心情 | 给时刻赋予情绪身份 |
| 时间轴 | 心情节点挂在轨道上 | 让每条记录一眼有情绪状态 |
| 筛选菜单 | 图标 + 心情名称 | 让用户按情绪缩小当前时间轴 |
| 筛选状态 | emoji + 心情名称 | 让当前条件轻量可见 |
| 预览页 | 心情节点 + 心情名称 | 强化单条时刻的情绪身份 |
| 热力图 | 日期格使用当天心情色 | 把情绪分布压缩成年度图案 |
| 统计页 | 心情色用于分布条和数量关系 | 让用户理解某一年情绪结构 |

可以把心情对象理解成这条链：

```text
一次记录选择“开心”
  -> 时间轴出现开心节点
  -> 筛选里可以选择开心
  -> 当前筛选显示开心状态
  -> 热力图对应日期呈现开心色
  -> 统计里开心参与年度分布
```

所以，心情节点只是心情对象在时间轴上的一种呈现。心情颜色也不是局部样式，而是跨时间轴、热力图、筛选和统计的一致语义。

## 标签对象

标签是时刻的主题线索。它帮助用户按“事情属于什么主题”整理记录。

```text
标签
  ├── 可以在编辑时刻时选择
  ├── 可以在编辑时临时创建
  ├── 可以在标签管理中集中维护
  ├── 可以作为首页筛选条件
  └── 删除标签不会删除时刻
```

标签和内容之间的关系是“归类”，不是“所有权”：

```text
删除标签
  -> 标签本身消失
  -> 已使用这个标签的时刻失去该标签
  -> 时刻的标题、正文、照片、时间和心情都保留
```

标签在时间轴里以 `#标签名` 的视觉出现，用来提示这条记录的主题。筛选时，标签会改变当前时间轴可见内容。

标签删除和时刻删除不是同一类动作。标签删除只是移除一个分类线索；时刻删除会改变一条记录的生命周期。

## 删除生命周期

删除不是一个孤立按钮，而是时刻对象的一段状态变化。它回答的是：用户暂时不想在时间轴看到这条记录，还是已经决定彻底放弃它。

```text
正常时刻
  -> 左滑露出删除动作
  -> 点击删除
  -> 进入垃圾箱
  -> 可恢复或彻底删除
```

首页删除的产品语义是“先移出主时间轴”。删除后，这条时刻不再出现在普通浏览、筛选、热力图回看和统计口径中，但它仍然保留在垃圾箱里，用户还有反悔空间。

垃圾箱是删除生命周期的管理区：

```text
垃圾箱里的时刻
  -> 右滑恢复
      -> 回到普通时刻
  -> 左滑彻底删除
      -> 结束恢复机会
```

恢复表示“这条记录重新属于我的生活时间轴”。恢复后，它再次带着原来的时间、心情、标签、文字和照片参与浏览、筛选、热力图表达和统计。

彻底删除表示“这条记录不再作为一个时刻存在”。它不是隐藏、归档或取消筛选，而是用户明确放弃恢复机会。

因此，删除生命周期有三层产品效果：

| 状态 | 用户看到的效果 | 产品语义 |
| --- | --- | --- |
| 普通时刻 | 出现在时间轴、筛选结果、热力图和统计口径中 | 这是正在使用的生活记录 |
| 垃圾箱时刻 | 从主时间轴消失，只在垃圾箱管理 | 暂时移除，但仍可找回 |
| 彻底删除 | 不再出现在任何记录管理中 | 用户放弃恢复机会 |

## 筛选逻辑

首页筛选当前由标签和心情组成。它的产品语义是：缩小当前时间轴，让用户只看满足条件的时刻。

```text
完整时间轴
  -> 选择标签
      -> 只看这个标签下的时刻
  -> 再选择心情
      -> 只看同时满足标签和心情的时刻
```

筛选结果会变成当前上下文标记：

```text
#生活
😊 开心
```

用户可以单独移除一个条件，也可以清除全部。筛选为空时，时间轴回到完整记录集合。

筛选的关键边界：

```text
标签 / 心情筛选
  -> 改变“当前看哪些记录”

热力图日期 / 月份选择
  -> 改变“去哪个时间位置看”
```

这两个行为不能混在一起。筛选是内容集合变化；热力图选择是时间定位。

## 上下文标记对象

上下文标记负责把“当前时间轴为什么变少、为什么跳到这里”显示出来。它不是内容本身，而是当前查看条件的可见说明。

```text
筛选标记
  -> #生活
  -> 😊 开心
  -> 说明当前只看满足条件的时刻

时间标记
  -> 2026
  -> 7 月
  -> 7 月 5 日
  -> 说明当前定位到某个年份、月份或日期
```

筛选标记和时间标记可以同时存在：

```text
#生活 + 😊 开心 + 7 月
  -> 只看 7 月里同时属于生活、心情为开心的时刻
```

用户移除筛选标记时，改变的是“看哪些记录”。用户移除时间标记时，改变的是“是否停在某个时间位置”。两者都表现为当前上下文的一部分，但含义不同。

## 热力图对象

热力图不是普通日历，也不是另一个独立页面。它是时间轴上的回看和定位对象。

热力图把记录压缩成年度视图：

```text
一年
  -> 月份
      -> 日期格
          -> 是否有记录
          -> 当天心情印象
          -> 当天记录数量
```

热力图里的颜色来自心情对象。某一天有记录时，日期格用这一天最后一条时刻的心情色表达当日情绪印象；没有记录时，日期格保持空状态。这样用户不用打开每条记录，也能看到一年里的情绪分布。

热力图当前有两种主要行为：

```text
切换年份
  -> 换一整年的回看范围
  -> 清除当前时间锚点

选择月份或日期
  -> 高亮对应时间
  -> 时间轴滚动到相关记录
  -> 再点同一位置可取消
```

当标签或心情筛选已经生效时，热力图也会跟随当前筛选口径，让用户看到“当前条件下的年度分布”。但日期或月份选择本身不改变筛选条件，它只负责定位，并通过时间标记让用户看见当前锚点。

可以这样理解：

```text
标签 / 心情
  -> 决定热力图和时间轴统计哪些记录

日期 / 月份
  -> 决定把时间轴带到哪里
```

如果用户选择的时间位置在当前筛选下没有可见记录，界面会提示当前条件下没有匹配记录，而不是自动改变筛选。

## 任务卡片层级

任务卡片层级说明“当前动作是临时任务”。它不描述有哪些设置页面，只描述卡片应该呈现的层级效果。

完整任务使用同一种视觉关系：

```text
底层上下文
  -> 上一层卡片
      -> 当前卡片
```

视觉效果是：

```text
当前卡片浮在最前
上一层卡片缩小、下沉、露在后面
更早层级暂时不显示
关闭当前卡片后，上一层重新回到前面
```

这种层级表达让用户知道：自己是在原场景上处理一个临时任务，而不是离开了主场景。

卡片对象只区分任务重量：

| 任务 | 交互效果 | 产品语义 |
| --- | --- | --- |
| 阅读类任务 | 弹出阅读卡片 | 临时查看一条记录 |
| 编辑类任务 | 弹出表单卡片 | 创建或修改一条记录 |
| 管理类任务 | 弹出管理卡片 | 进入长期管理区 |
| 权益类任务 | 弹出权益卡片 | 在触达限制时解释权益 |

用户关闭最前面的卡片时，上一层卡片重新成为当前任务；关闭最后一张卡片时，才回到时间轴。

## 就近浮窗面板

轻量选择不使用完整任务卡片，也不从屏幕底部升起半页面板，而是从触发元素旁边就近弹出一个浮窗。

浮窗是一个依附锚点的临时浮层：

```text
就近浮窗
  ├── 有明确锚点：它属于刚才点的那个入口或字段
  ├── 带指向锚点的尖角：表达“这些选项来自这里”
  ├── 尺寸随内容自适应：选项少就小，不铺满固定半屏
  └── 是同层浮层：不改变页面层级
```

每个轻量选择都从自己的触发元素就近打开：

| 选择动作 | 锚点 | 打开位置 |
| --- | --- | --- |
| 标签筛选 | 时间轴顶部的筛选入口 | 从入口就近弹出 |
| 心情筛选 | 时间轴顶部的筛选入口 | 从入口就近弹出 |
| 日期选择 | 编辑卡片里的日期字段 | 贴着字段就近弹出 |
| 时间选择 | 编辑卡片里的时间字段 | 贴着字段就近弹出 |

浮窗的定位策略保证“就近”且尽量不遮挡当前上下文：

```text
优先在锚点下方展开
  -> 下方空间不足时翻转到锚点上方
  -> 水平方向贴近锚点，并保持在安全区内
  -> 当前上下文（时间轴或编辑卡片）大部分仍然可见
```

就近浮窗的产品语义是“就地调整”：

- 用户仍在当前上下文里。
- 浮窗只是临时露出选项。
- 选完后浮窗收起，点浮窗外部也收起。
- 不制造新的页面层级。

浮窗和任务卡片是两种不同的层级关系：

```text
任务卡片
  -> 背景下沉、上一层缩小，进入卡片层级栈

就近浮窗
  -> 背景不下沉、不缩小，是同层临时浮层，不入层级栈
```

因此，筛选、日期、时间更像临时工具；预览、编辑、设置更像完整任务。

筛选浮窗从时间轴的筛选入口打开，因为它改变当前时间轴看哪些记录。日期和时间浮窗从编辑卡片的对应字段打开，因为它们只是在编辑一条时刻的具体字段。

## 对象之间如何组合

HeatMoment 的核心交互可以用一条链表示：

```text
时刻
  带着时间、心情、标签和内容进入时间轴

时间轴
  用时间戳、心情节点和气泡展示时刻

心情
  用名称、emoji、图标、颜色贯穿筛选、节点、热力图和统计

标签
  用 #标签名组织主题，并改变时间轴可见内容

上下文标记
  用标签、心情、年份、月份和日期说明当前时间轴条件

热力图
  用日期格和心情色展示年度分布，并把时间轴带回某个时间点

任务卡片
  用卡片层级承接预览、编辑和管理任务

就近浮窗面板
  用就近浮窗承接局部选择，不改变页面层级

删除生命周期
  用垃圾箱和恢复动作管理时刻是否仍属于主时间轴
```

如果新增交互，应先判断它属于哪个对象：

| 新交互想表达什么 | 应归属的对象 |
| --- | --- |
| 一条记录的内容、时间、照片 | 时刻对象 |
| 情绪状态、颜色、图标、统计 | 心情对象 |
| 主题分类、整理、筛选 | 标签对象 |
| 当前看的是哪些记录、定位在哪段时间 | 上下文标记 |
| 年度分布、日期回看、时间定位 | 热力图对象 |
| 暂时移出、恢复、彻底移除一条记录 | 删除生命周期 |
| 临时阅读、编辑、设置管理 | 任务卡片 |
| 就地选择一个条件或值 | 就近浮窗面板 |

这样做可以避免把交互做成散装入口，也能保证同一个对象在不同页面里保持同一套语义。

## 当前不表达的能力

以下内容不属于当前产品对象体系：

- 独立一级回看页面。
- 深度时间范围筛选。
- 云同步、社交发布、多端协同。
- 复杂 AI 分析。
- 已开放的皮肤市场或自定义皮肤下载。
- Face ID、语言切换和作者其他应用入口的实际功能。

后续新增这些能力时，应先明确它们属于现有对象扩展，还是需要成为新的产品对象。
